> 실행예제

게스트 OS 내부에서 네트워크 트래픽 급증 시 패킷 유실(`rx dropped`)이 발생할 때, 가상 NIC 드라이버 종류(`VMXNET3` vs `E1000/E1000e`)를 식별하고 하드웨어 링 버퍼(Ring Buffer) 포화 상태 및 ESXi 가상 스위치 드롭 통계를 점검합니다.

```bash
# 1. 게스트 OS 관점: 인터페이스별 패킷 드롭 및 에러 카운터 확인
$ ip -s link show eth0
# 2: eth0: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500 qdisc mq state UP mode DEFAULT group default qlen 1000
#     link/ether 00:50:56:9a:1b:2c brd ff:ff:ff:ff:ff:ff
#     RX: bytes  packets  errors  dropped overrun mcast
#     4521405012 35412090      0   154020       0     0
#     TX: bytes  packets  errors  dropped carrier collsns
#     2140501240 18504010      0        0       0     0
# -> RX 수신 단에서 15만 건 이상의 패킷 드롭(dropped) 발생 확인

# 2. 현재 로드된 가상 NIC 드라이버 모듈 및 하드웨어 모델 확인
$ ethtool -i eth0
# driver: vmxnet3 (또는 e1000, e1000e)
# version: 1.6.0.0-k-NAPI
# firmware-version: N/A
# bus-info: 0000:0b:00.0

# 3. ethtool 상세 통계로 드롭 사유 분석 (링 버퍼 고갈 여부)
$ ethtool -S eth0 | grep -iE "drop|miss|err|overflow"
# [VMXNET3 출력 예시]
#      rx_drops: 154020
#      rx_dropped: 154020
#      rx_buf_alloc_err: 0
#      rx_ring0_drops: 142010
#      rx_ring1_drops: 12010
# -> 커널 수신 링 버퍼 큐(ring0, ring1)가 꽉 차서 하드웨어 수준에서 버려짐 확인

# 4. 현재 적용된 NIC 링 버퍼 크기와 하드웨어 최대 허용치(Pre-set Maximums) 비교
$ ethtool -g eth0
# Ring parameters for eth0:
# Pre-set maximums:
# RX:             4096
# RX Mini:           0
# RX Jumbo:       2048
# TX:             4096
# Current hardware settings:
# RX:             1024
# RX Mini:           0
# RX Jumbo:        512
# TX:              512
# -> 현재 RX 버퍼가 1024로 설정되어 있어 최대치인 4096까지 4배 확장 가능함

# 5. ESXi 호스트 관점: 가상 스위치 포트 레벨 드롭 확인 (esxtop n 뷰)
# ESXi SSH 콘솔에서 'esxtop' 실행 후 'n'(네트워크 뷰) 진입
# PORT-ID    USED-BY           %DRPRX    %DRPTX
# 67108870   Web-Server-01.eth0   4.25      0.00
# -> %DRPRX 가 0% 이상이면 ESXi 가상 스위치 단에서 버퍼 초과로 패킷을 드롭 중임을 확인
```

## 스크립트

리눅스 게스트 OS에서 실행되어 현재 장착된 가상 NIC 어댑터 유형을 식별하고, 비효율적인 E1000 계열 어댑터를 감지하면 VMXNET3 교체를 권고하며, VMXNET3 환경에서 발생한 RX 패킷 드롭을 해소하기 위해 링 버퍼(`Ring Buffer`)를 최대치(4096)로 자동 증설해 주는 진단/튜닝 쉘 스크립트입니다.

```bash
#!/bin/bash
# tune_vmware_nic.sh - Diagnose packet drops and tune Ring Buffer on VMware virtual NICs

NIC_NAME=${1:-""}

echo "=========================================="
echo " [VMware 가상 NIC 패킷 유실 진단 및 튜닝]"
echo "=========================================="

if [ "$EUID" -ne 0 ]; then
    echo "  [오류] 네트워크 장치 설정을 변경하려면 루트(root) 권한이 필요합니다."
    exit 1
fi

if ! command -v ethtool &>/dev/null; then
    echo "  [오류] ethtool 유틸리티가 설치되어 있지 않습니다."
    exit 1
fi

# 1. 대상 인터페이스 결정
if [ -z "$NIC_NAME" ]; then
    NIC_NAME=$(ip route | awk '/default/ {print $5}' | head -n 1)
fi

echo "  대상 인터페이스: ${NIC_NAME:-"감지 실패"}"

if [ -z "$NIC_NAME" ] || ! ip link show "$NIC_NAME" &>/dev/null; then
    echo "  [오류] 유효한 네트워크 인터페이스를 찾을 수 없습니다."
    exit 1
fi

# 2. 가상 NIC 어댑터 드라이버 식별
DRIVER_NAME=$(ethtool -i "$NIC_NAME" 2>/dev/null | awk '/driver:/ {print $2}')
echo -e "\n[1] 드라이버 및 어댑터 아키텍처 점검:"
echo "  - 감지된 드라이버: ${DRIVER_NAME}"

case "$DRIVER_NAME" in
    e1000|e1000e)
        echo "  [치명적 권고] 현재 레거시 에뮬레이션 드라이버(${DRIVER_NAME})를 사용 중입니다!"
        echo "  - 사유: E1000은 Intel 82545EM 하드웨어를 에뮬레이트하므로 호스트 CPU 부하가 극심하고 다중 큐(Multi-Queue/RSS)를 지원하지 않아 패킷 유실에 매우 취약합니다."
        echo "  - 조치: vSphere Client에서 가상 머신 네트워크 어댑터 유형을 'VMXNET3'로 변경하십시오."
        ;;
    vmxnet3)
        echo "  [정상] VMware 반가상화(Paravirtualized) 전용 드라이버(VMXNET3)가 장착되어 있습니다."
        ;;
    *)
        echo "  - 비 VMware 계열 또는 표준 물리 드라이버(${DRIVER_NAME})입니다."
        ;;
esac

# 3. RX 패킷 드롭 현황 점검
echo -e "\n[2] RX 패킷 드롭 및 에러 통계:"
RX_DROPPED=$(ip -s link show "$NIC_NAME" | awk '/RX:/ {getline; print $4}')
echo "  - 누적 RX 패킷 드롭 수: ${RX_DROPPED} 건"

# 4. 링 버퍼(Ring Buffer) 설정 확인 및 증설
echo -e "\n[3] 링 버퍼(Ring Buffer) 크기 점검 및 확장:"
RING_INFO=$(ethtool -g "$NIC_NAME" 2>/dev/null)

MAX_RX=$(echo "$RING_INFO" | awk '/Pre-set maximums:/,/Current hardware settings:/' | awk '/RX:/ {print $2}' | head -n 1)
CURR_RX=$(echo "$RING_INFO" | awk '/Current hardware settings:/,/^$/' | awk '/RX:/ {print $2}' | head -n 1)

echo "  - 지원 최대 RX 크기 : ${MAX_RX}"
echo "  - 현재 적용 RX 크기 : ${CURR_RX}"

if [ -n "$MAX_RX" ] && [ -n "$CURR_RX" ] && [ "$CURR_RX" -lt "$MAX_RX" ]; then
    echo "  -> 현재 링 버퍼가 최대치에 미치지 못합니다. ${CURR_RX} -> ${MAX_RX} 확장 적용 중..."
    ethtool -G "$NIC_NAME" rx "$MAX_RX" tx "$MAX_RX" 2>/dev/null
    
    # 튜닝 결과 재확인
    NEW_RX=$(ethtool -g "$NIC_NAME" 2>/dev/null | awk '/Current hardware settings:/,/^$/' | awk '/RX:/ {print $2}' | head -n 1)
    echo "  [완료] 링 버퍼가 ${NEW_RX} 크기로 확장되었습니다."
    
    # 영구 적용 가이드 안내
    echo "  [알림] 재부팅 후에도 유지하려면 네트워크 설정 스크립트(/etc/rc.local 또는 NetworkManager 디스패처)에 'ethtool -G ${NIC_NAME} rx ${MAX_RX} tx ${MAX_RX}' 명령을 등록하십시오."
else
    echo "  [정상] 링 버퍼가 이미 최대 허용치(${MAX_RX})로 구성되어 있습니다."
fi

# 5. OS 커널 수신 큐(netdev_max_backlog) 최적화 제안
echo -e "\n[4] 커널 네트워크 수신 버퍼 파라미터 점검:"
BACKLOG=$(sysctl -n net.core.netdev_max_backlog)
echo "  - 현재 net.core.netdev_max_backlog: ${BACKLOG}"
if [ "$BACKLOG" -lt 5000 ]; then
    echo "  -> 트래픽 폭증 시 커널 큐 드롭 방지를 위해 10000 이상으로 상향을 권장합니다."
    echo "  -> 즉시 적용: sysctl -w net.core.netdev_max_backlog=10000"
fi

echo -e "\n=========================================="
echo " [진단 및 튜닝 완료]"
echo "=========================================="
```

## 해설

VMware ESXi 가상화 환경에서 대량의 트래픽(순간적인 버스트 트래픽, 초당 수만 패킷 이상)이 인입될 때 패킷이 유실되어 서비스 응답 속도가 느려지는 문제는 주로 **1) 에뮬레이션 가상 어댑터(E1000/E1000e)의 태생적 아키텍처 한계**와 **2) 반가상화 어댑터(VMXNET3)의 수신 링 버퍼(Ring Buffer) 크기 부족**으로 인해 발생합니다.

### 1. VMXNET3 vs E1000 / E1000e 핵심 비교

| 비교 항목 | E1000 / E1000e | VMXNET3 (권장) |
| :--- | :--- | :--- |
| **작동 방식** | 레거시 Intel 82545EM/82574 **하드웨어 완전 에뮬레이션** | 하이퍼바이저와 직접 통신하는 **반가상화(Paravirtualized)** |
| **CPU 오버헤드** | 가상 하드웨어 인터럽트 처리로 인해 **호스트 CPU 사용량 극심** | 공유 메모리 통신으로 **최소한의 CPU 사용량** 보장 |
| **다중 큐 (RSS)** | **미지원** (단일 vCPU 코어에 모든 트래픽 인터럽트 집중) | **지원** (vCPU 개수만큼 다중 수신 큐(RSS) 분산 처리) |
| **오프로드 기능** | 기본 TSO만 부분 지원 | **TSO, LRO, VxLAN/Geneve 오프로드 완벽 지원** |
| **대역폭 처리량** | 1 Gbps 제약 및 버스트 처리 시 패킷 드롭 다발 | 10G / 25G / 40G+ 고속 대역폭 무손실 수용 |

* **E1000/E1000e의 치명적 한계**:
  * 구형 OS 설치 편의를 위해 제공되는 하드웨어 에뮬레이션 모델입니다. 패킷 1개가 인입될 때마다 하이퍼바이저가 x86 인터럽트 콘텍스트 스위칭을 발생시키므로, 트래픽이 조금만 몰려도 1번 vCPU가 인터럽트 처리(`%si`)로 100% 포화되면서 이후 들어오는 패킷을 대량으로 버려버립니다(`rx_dropped`).

### 2. VMXNET3에서 패킷 드롭이 발생하는 원인 및 메커니즘

VMXNET3를 사용하더라도 기본 설정 상태에서는 순간적인 마이크로 버스트(Micro-burst) 트래픽 발생 시 패킷이 드롭될 수 있습니다.

1. **기본 RX 링 버퍼 크기의 한계 (기본값: 1024 / 2048)**:
   * 리눅스 커널 드라이버 로드 시 기본 RX 링 버퍼 크기는 1024(또는 2048)로 작게 잡혀 있습니다. 패킷이 쏟아져 들어올 때 게스트 OS 커널의 NAPI 폴링 루틴이 버퍼를 비우기 전에 하드웨어 링이 가득 차면 VMXNET3는 신규 패킷을 즉시 폐기(`rx_drops`)합니다.
2. **ESXi 가상 스위치(vSwitch) 포트 버퍼 고갈**:
   * 게스트 OS뿐만 아니라 ESXi 호스트 단에서도 드라이버가 패킷을 꺼내가지 못하면 vSwitch 포트 큐가 차올라 `esxtop` 상의 `%DRPRX` 수치가 치솟습니다.
3. **vCPU 개수 부족으로 인한 RSS 큐 처리 지연**:
   * 네트워크 수신 스케일링(RSS)이 vCPU 코어 수에 맞게 분산되지 않아 특정 코어에만 소프트웨어 인터럽트(ksoftirqd)가 병목을 일으키는 경우입니다.

### 3. 단계별 튜닝 및 영구 해결 가이드

#### 1) 어댑터 교체 (E1000 $\rightarrow$ VMXNET3)
운영 중인 가상 머신의 어댑터가 E1000으로 되어 있다면, vSphere Client에서 가상 머신 설정 편집을 통해 네트워크 어댑터를 **VMXNET3**로 교체해야 합니다 (새 어댑터 추가 후 기존 E1000 삭제, IP 재설정 필요).

#### 2) RX / TX 링 버퍼를 하드웨어 최대치(4096)로 확장
```bash
# 즉시 최대치로 확장 (무중단 적용)
sudo ethtool -G eth0 rx 4096 tx 4096
```

* **재부팅 후 영구 적용 설정**:
  * **RHEL / Rocky / CentOS (`NetworkManager`)**:
    ```bash
    nmcli connection modify eth0 ethtool.ring-rx 4096 ethtool.ring-tx 4096
    nmcli connection up eth0
    ```
  * **Ubuntu / Debian (`netplan` 또는 `rc.local`)**:
    `/etc/rc.local` 파일에 아래 구문 추가 후 실행 권한 부여:
    ```bash
    /sbin/ethtool -G eth0 rx 4096 tx 4096
    ```

#### 3) OS 커널 네트워크 백로그 큐 상향
네트워크 카드에서 커널로 전달되는 대기열 큐를 늘려 버스트 트래픽 수용력을 극대화합니다.

```bash
# /etc/sysctl.d/99-network-tuning.conf
net.core.netdev_max_backlog = 10000
net.core.rmem_max = 16777216
net.core.wmem_max = 16777216
```
* 적용 명령어: `sudo sysctl --system`

## 주의사항

1. **E1000 사용 시 ESXi 호스트 PSOD(Purple Screen of Death) 버그 위험**:
   * 과거 다수의 ESXi 버전에서 대용량 트래픽이 유입될 때 E1000 가상 디바이스의 메모리 버퍼 오버플로우로 인해 **ESXi 하이퍼바이저 전체가 퍼플스크린(PSOD)을 띄우며 다운되는 치명적 버그**가 보고되었습니다. 운영 환경에서는 이유를 불문하고 E1000 어댑터를 전면 배제하고 VMXNET3를 표준화해야 합니다.

2. **링 버퍼 증설 시 게스트 OS 메모리 점유율 증가 고려**:
   * `ethtool -G rx 4096`으로 버퍼를 4배 늘리면 각 큐마다 할당되는 커널 sk_buff 메모리 공간이 증가합니다. 메모리가 극도로 작게 할당된 미니멀 VM(예: 512MB RAM)의 경우 커널 메모리 경합이 발생할 수 있으므로 최소 2GB 이상의 메모리를 확보한 상태에서 튜닝해야 합니다.

3. **게스트 LRO(Large Receive Offload) 활성화 시 라우터/방화벽 VM 주의**:
   * VMXNET3의 LRO 기능은 일반 엔드포인트 웹/WAS/DB 서버에는 성능 향상을 주지만, 가상 머신이 **소프트웨어 라우터(pfSense, VyOS)나 패킷 포워딩 게이트웨이 역할을 하는 경우 LRO로 인해 패킷 체크섬이 왜곡되거나 포워딩 패킷이 드롭**될 수 있으므로 게이트웨이 장비에서는 `ethtool -K eth0 lro off`로 꺼두어야 합니다.
